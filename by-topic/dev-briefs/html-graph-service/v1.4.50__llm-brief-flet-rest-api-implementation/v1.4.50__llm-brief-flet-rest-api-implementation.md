## 1. Executive Summary

### 1.1 What We're Building

A comprehensive REST API layer that exposes FLeT (Flow-Level Execution Task) operations for HTML caching, retrieval, and observability. The API provides multiple abstraction levels to serve different client needs - from low-level cache operations to high-level domain-specific workflows.

### 1.2 Why We're Building It

The FLeT pipeline has proven powerful for HTML processing with built-in observability (flow data, task tracking, duration capture). Multiple clients need access to these capabilities:

| Client | Use Case |
|--------|----------|
| **html-client service UI** | Interactive HTML caching and visualization |
| **MitmProxy service** | Automated HTML capture and storage |
| **FLeT Visualization UIs** | Debugging, monitoring, workflow visualization |
| **Future Orchestrators** | Composing FLeTs into larger pipelines |

Just as exposing cache internals via REST enabled powerful debugging during FLeT development, exposing FLeT internals will empower clients to build sophisticated HTML processing applications.

### 1.3 Design Approach

**Principle 1: Separation of Concerns**
- `/cache/*` routes handle generic cache operations (entity management, data files)
- `/flet/*` routes handle FLeT-specific operations (flow execution, observability)
- Cache routes are designed for future migration to Cache Service

**Principle 2: Multiple Abstraction Levels**
- Low-level routes for fine-grained control (requires `cache_id`)
- Domain-level routes for convenience (handles entity creation/lookup)
- Full observability routes (flow data, logs, tasks, durations)

**Principle 3: Thin Routes, Rich Services**
- Route classes handle ONLY: request parsing, service calls, response formatting, errors
- Service classes handle ALL: business logic, entity management, FLeT orchestration

**Principle 4: Consistent URL Patterns**
- `{namespace}` always in path (matches Cache Service patterns)
- `{cache_id}` in path for entity-specific operations
- `{data_key:path}` for hierarchical data paths
- POST for operations with request bodies, GET for retrieval


## 3. Route Specifications

### 3.1 Cache Entity Routes (`/cache/{namespace}/entity/`)

| Route | Method | Request Body | Response | Notes |
|-------|--------|--------------|----------|-------|
| `/create` | POST | `{cache_key, file_id?}` | `{cache_id, created}` | Creates new entity |
| `/lookup` | POST | `{cache_key?, cache_hash?}` | `{cache_id, found}` | Find existing |
| `/{cache_id}` | GET | - | Entry JSON | Full entry data |
| `/{cache_id}/metadata` | GET | - | Metadata JSON | Just metadata |
| `/{cache_id}/refs` | GET | - | Refs JSON | Just refs |
| `/{cache_id}/exists` | GET | - | `{exists: bool}` | Quick check |
| `/{cache_id}` | DELETE | - | `{deleted: bool}` | Remove entity |

### 3.2 Cache Data Routes (`/cache/{namespace}/data/{cache_id}/`)

| Route | Method | Request Body | Response | Notes |
|-------|--------|--------------|----------|-------|
| `/` | GET | - | File list | `recursive` query param |
| `/paths` | GET | - | Path list | Just paths |
| `/string/{data_key:path}/{data_file_id}` | GET | - | String content | Raw string |
| `/json/{data_key:path}/{data_file_id}` | GET | - | JSON content | Parsed JSON |
| `/store/string/{data_key:path}/{data_file_id}` | POST | string body | Store response | Create new |
| `/store/json/{data_key:path}/{data_file_id}` | POST | JSON body | Store response | Create new |
| `/string/{data_key:path}/{data_file_id}` | PUT | string body | `{success}` | Update existing |
| `/json/{data_key:path}/{data_file_id}` | PUT | JSON body | `{success}` | Update existing |
| `/exists/{data_type}/{data_key:path}/{data_file_id}` | GET | - | `{exists}` | data_type: string\|json |
| `/{data_type}/{data_key:path}/{data_file_id}` | DELETE | - | `{deleted}` | Remove file |

### 3.3 FLeT Flow Routes (`/flet/flows/{namespace}/{cache_id}/`)

| Route | Method | Response | Notes |
|-------|--------|----------|-------|
| `/` | GET | `{flets: [names]}` | List FLeTs that have executed |
| `/{flet_name}` | GET | Full flow JSON | Complete flow data |
| `/{flet_name}/logs` | GET | Log entries | Just logs |
| `/{flet_name}/tasks` | GET | Task list | Task breakdown |
| `/{flet_name}/durations` | GET | Duration dict | Timing info |

### 3.4 FLeT Execution Routes (Low-Level)

| Route | Method | Request Body | Response |
|-------|--------|--------------|----------|
| `/flet/html/to/cache/{namespace}/{cache_id}` | POST | `{html, data_key?, data_file_id?}` | `{success, char_count, store_response}` |
| `/flet/html/from/cache/{namespace}/{cache_id}` | POST | `{data_key?, data_file_id?}` | `{success, html, found}` |

### 3.5 FLeT Domain Routes (Orchestrated)

**Store Operations:**

| Route | Method | Request Body | Response |
|-------|--------|--------------|----------|
| `/flet/html/store/{namespace}/raw` | POST | `{html}` | `{success, cache_id, cache_key, created_entity, char_count}` |
| `/flet/html/store/{namespace}/url` | POST | `{url, timeout?}` | `{success, cache_id, cache_key, created_entity, char_count, final_url}` |
| `/flet/html/store/{namespace}/key/{cache_key:path}` | POST | `{html}` | `{success, cache_id, cache_key, created_entity, char_count}` |

**Load Operations:**

| Route | Method | Request Body | Response |
|-------|--------|--------------|----------|
| `/flet/html/load/{namespace}/id` | POST | `{cache_id}` | `{success, html, found, cache_id}` |
| `/flet/html/load/{namespace}/hash` | POST | `{cache_hash}` | `{success, html, found, cache_id}` |
| `/flet/html/load/{namespace}/key/{cache_key:path}` | POST | `{}` | `{success, html, found, cache_id}` |
| `/flet/html/load/{namespace}/url` | POST | `{url}` | `{success, html, found, cache_id}` |

## 7. Implementation Examples

### 7.1 Route Class Pattern (Thin Routes)

```python
# Routes__FLeT__Html__Domain.py

class Routes__FLeT__Html__Domain(Fast_API__Routes):
    tag     : str                  = 'flet-html'
    service : FLeT__Html__Service  = None
    
    def store__raw(self                              ,
                   namespace: str                    ,
                   request  : Schema__Html__Store__Raw__Request
              ) -> Schema__Html__Store__Response:
        """POST /flet/html/store/{namespace}/raw"""
        try:
            return self.service.store_raw(namespace = namespace    ,
```

```python
                              namespace : str          ,
                              cache_key : str          ,
```

```python
# FLeT__Flows__Service.py

class FLeT__Flows__Service(Type_Safe):
    cache_client : Html_Cache__Client = None
    
    def list_flets(self                ,
                   namespace : str     ,
                   cache_id  : Cache_Id
              ) -> list[str]:
        """List all FLeTs that have executed for this entity"""
        
        entity = Cache__Entity(cache_client = self.cache_client.cache_client,
                               cache_id     = cache_id                      ,
                               namespace    = namespace                     )
        
        # List files under flows/ data key
        files = entity.data__files(data_key='flows', recursive=True)
        
        # Extract FLeT names from paths like 'flows/html-to-cache/flow-data.json'
        flet_names = set()
        for file in files:
            parts = file.get('path', '').split('/')
            if len(parts) >= 2 and parts[0] == 'flows':
                flet_names.add(parts[1])
        
        return sorted(list(flet_names))
    
    def get_flow(self                  ,
                 namespace  : str      ,
                 cache_id   : Cache_Id ,
                 flet_name  : str
            ) -> dict:
        """Get full flow data for a specific FLeT execution"""
        
        json_file = Cache__Entity__Json_File(cache_client = self.cache_client.cache_client,
                                             cache_id     = cache_id                      ,
                                             namespace    = namespace                     ,
                                             data_key     = f'flows/{flet_name}'          ,
                                             data_file_id = 'flow-data'                   )
        
        if not json_file.exists():
            raise ValueError(f"Flow data not found for FLeT: {flet_name}")
        
        return json_file.retrieve()
    
    def get_logs(self                  ,
                 namespace  : str      ,
                 cache_id   : Cache_Id ,
                 flet_name  : str
            ) -> list:
        """Get just the logs from flow data"""
        flow_data = self.get_flow(namespace, cache_id, flet_name)
        return flow_data.get('flow_data', {}).get('logs', [])
    
    def get_tasks(self                 ,
                  namespace  : str     ,
                  cache_id   : Cache_Id,
                  flet_name  : str
             ) -> list:
        """Get just the tasks from flow data"""
        flow_data = self.get_flow(namespace, cache_id, flet_name)
        return flow_data.get('flow_data', {}).get('tasks', [])
    
    def get_durations(self             ,
                      namespace  : str ,
                      cache_id   : Cache_Id,
                      flet_name  : str
                 ) -> dict:
        """Get task durations from flow data"""
        tasks = self.get_tasks(namespace, cache_id, flet_name)
        durations = {}
        for task in tasks:
            task_name = task.get('task_name', 'unknown')
            start     = task.get('start_time')
            end       = task.get('end_time')
            if start and end:
                # Calculate duration (simplified)
                durations[task_name] = {'start': start, 'end': end}
        return durations
```

## 11. Summary

This implementation provides:

1. **Complete REST API** for FLeT operations at multiple abstraction levels
2. **Clear separation** between cache operations and FLeT operations
3. **Rich observability** through flow data endpoints
4. **Flexible client support** from low-level control to high-level convenience
5. **Clean architecture** with thin routes and rich services
6. **Future-proof design** with cache routes ready for migration to Cache Service

The API enables clients to:
- Store HTML from raw content, URLs, or explicit keys
- Load HTML by cache_id, cache_hash, cache_key, or URL
- Inspect flow execution data, logs, tasks, and durations
- Directly manipulate cache entities and data files
- Build sophisticated HTML processing applications on top of FLeT
