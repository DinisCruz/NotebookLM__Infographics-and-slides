# Implementation Brief: In-Memory Service Pattern for FastAPI Microservices

**Version**: v1.5.0  
**Date**: January 2025  
**Scope**: mgraph_ai_service_cache, mgraph_ai_service_cache_client, mgraph_ai_service_html_graph

---

## Executive Summary

This brief describes the implementation of an **In-Memory Service Pattern** that enables FastAPI microservices to run in three modes:

1. **Full Remote** — All services accessed via HTTP (production)
2. **Full In-Memory** — All services run in-process via TestClient (testing)
3. **Hybrid** — Mix of remote and in-memory services (flexible development/testing)

The pattern achieves this through **dependency injection at the request layer**, ensuring client packages never require service package dependencies in remote mode, while enabling seamless in-memory testing when service packages are available.

## Part 1: The Problem

### Current Pain Points

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        CURRENT TESTING APPROACH                             │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   Test Setup                                                                │
│   ──────────                                                                │
│   1. Create FastAPI app                                                     │
│   2. Create Fast_API_Server(app)         ◄── Starts actual HTTP server     │
│   3. server.start()                      ◄── Binds to real port            │
│   4. Get server.url()                    ◄── http://localhost:random_port  │
│   5. Create client with base_url         ◄── Client talks over HTTP        │
│   6. Run tests                                                              │
│   7. server.stop()                       ◄── Must cleanup                   │
│                                                                             │
│   Problems:                                                                 │
│   • Slow startup (HTTP server initialization)                               │
│   • Port conflicts in parallel tests                                        │
│   • Server lifecycle management (start/stop)                                │
│   • Network overhead even for local tests                                   │
│   • Flaky tests due to timing/network issues                                │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### The Insight

Starlette's `TestClient` can call FastAPI apps **directly in-process** via ASGI — no HTTP server needed. The client doesn't care if it's talking to `TestClient` or `requests.Session`; both have the same interface (`.get()`, `.post()`, etc.).

### The Key: Request Layer Abstraction

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    *__REQUESTS CLASS - THE MAGIC                            │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   class Service__Client__Requests(Type_Safe):                               │
│       config: Service__Client__Config                                       │
│                                                                             │
│       def execute(self, method, path, body, headers):                       │
│           │                                                                 │
│           ├──► if config.mode == IN_MEMORY:                                 │
│           │        │                                                        │
│           │        ▼                                                        │
│           │    ┌────────────────────────────────────────┐                   │
│           │    │ TestClient(config.fast_api_app)        │                   │
│           │    │     .post(path, json=body, headers=h)  │                   │
│           │    │                                        │                   │
│           │    │ • Direct ASGI call                     │                   │
│           │    │ • No HTTP server                       │                   │
│           │    │ • No network                           │                   │
│           │    │ • Instant response                     │                   │
│           │    └────────────────────────────────────────┘                   │
│           │                                                                 │
│           └──► else (REMOTE):                                               │
│                    │                                                        │
│                    ▼                                                        │
│                ┌────────────────────────────────────────┐                   │
│                │ requests.Session()                     │                   │
│                │     .post(base_url + path, json=body)  │                   │
│                │                                        │                   │
│                │ • HTTP over network                    │                   │
│                │ • Real service endpoint                │                   │
│                │ • Production mode                      │                   │
│                └────────────────────────────────────────┘                   │
│                                                                             │
│   CRITICAL: The client code above this layer is IDENTICAL for both modes   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## Part 3: Composition Scenarios

### Scenario 1: Full In-Memory (Testing)

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    FULL IN-MEMORY (Test Environment)                        │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   pip install mgraph_ai_service_cache        (dev dependency)               │
│   pip install mgraph_ai_service_html_graph   (dev dependency)               │
│                                                                             │
│   ┌───────────────────────────────────────────────────────────────────┐     │
│   │                         TEST CODE                                  │     │
│   ├───────────────────────────────────────────────────────────────────┤     │
│   │                                                                    │     │
│   │   # 1. Create cache service in-memory                              │     │
│   │   cache_in_memory = Cache__Service__In_Memory().setup()            │     │
│   │                           │                                        │     │
│   │                           │ fast_api_app                           │     │
│   │                           ▼                                        │     │
│   │   # 2. Create cache client pointing to in-memory app               │     │
│   │   cache_client = (Client__Cache__Service()                         │     │
│   │                      .set__fast_api_app(cache_in_memory.fast_api_app)   │
│   │                      .client())                                    │     │
│   │                           │                                        │     │
│   │                           │ injected                               │     │
│   │                           ▼                                        │     │
│   │   # 3. Create html_graph service, inject cache client              │     │
│   │   html_graph_in_memory = (Html_Graph__Service__In_Memory()         │     │
│   │                              .setup(cache_client=cache_client))    │     │
│   │                           │                                        │     │
│   │                           │ fast_api_app                           │     │
│   │                           ▼                                        │     │
│   │   # 4. Create html_graph client                                    │     │
│   │   html_graph_client = (Client__Html_Graph__Service()               │     │
│   │                           .set__fast_api_app(html_graph_in_memory.fast_api_app)
│   │                           .client())                               │     │
│   │                                                                    │     │
│   │   # 5. Use normally - zero network, instant responses              │     │
│   │   result = html_graph_client.store_html(url, html)                 │     │
│   │                                                                    │     │
│   └───────────────────────────────────────────────────────────────────┘     │
│                                                                             │
│   Benefits:                                                                 │
│   • Tests run in milliseconds                                               │
│   • No port conflicts                                                       │
│   • No server lifecycle                                                     │
│   • Deterministic (no network flakiness)                                    │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## Summary

This pattern enables **zero-compromise flexibility**:

1. **Testing**: Full in-memory stack, millisecond tests, no flakiness
2. **Development**: Mix local and remote services as needed
3. **Production**: Pure client packages, no service dependencies

The key insight is that **the `*__Requests` class is the only injection point**. Everything above it is mode-agnostic. This keeps the client code clean and the dependency graph minimal.
