## Overview

A special deployment mode of the MITM Proxy platform where all microservice components (caching, HTML processing, graph generation, text transformation) run in a single process or container. This mode enables the entire system to function offline in air-gapped environments by embedding each service in-memory, simplifying deployment and enabling end-to-end testing without external dependencies.

The same codebase can run as independent serverless functions, as microservices on Kubernetes, or as a one-shot monolithic application depending on the deployment needs.

## Key Topics

- **Single-Process Deployment**: All normally separate services started within one Python process/container
- **In-Memory Service Calls**: Inter-service communication via FastAPI TestClient instead of HTTP sockets
- **Client Abstraction Layer**: Switchable mode between live HTTP requests and in-memory calls
- **Integration Testing**: Fast end-to-end tests exercising real code paths without network overhead
- **Air-Gapped Operation**: Complete offline functionality with no external network dependencies

## Architecture Highlights

- **FastAPI TestClient**: Starlette's TestClient provides same interface as HTTP client but runs entirely in-memory
- **Service Client Abstraction**: Each microservice client module can choose between real HTTP and TestClient calls
- **Dependency Injection**: FastAPI dependency overrides provide in-memory clients during test mode
- **Shared Memory Space**: All services share the same runtime, eliminating network overhead

## Use Cases

**Primary - Integration Testing:**
- Full in-memory stack boots in few hundred milliseconds
- Validates complex workflows (caching, HTML parsing, graph building) deterministically
- Exercises real code paths across services without mocking

**Secondary - Lightweight Deployments:**
- Development/staging environments without full microservice infrastructure
- Client demos running entirely on laptop (no network required)
- MVP deployments where cloud microservices aren't justified

## Limitations

- Not suitable for heavy production traffic (single process, no horizontal scaling)
- Some external integrations may still require network access
- Memory leaks or heavy CPU in one component affects all others
