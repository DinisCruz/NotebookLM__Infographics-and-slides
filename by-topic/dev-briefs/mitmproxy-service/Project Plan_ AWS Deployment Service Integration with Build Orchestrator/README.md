## Overview

A comprehensive project plan for creating an AWS integration web service that works with an existing build orchestrator to automate complete AWS environment setup and teardown on-demand. The service exposes fine-grained AWS operations (primitives) as REST API endpoints while the orchestrator sequences these operations to provision or destroy infrastructure.

Similar in spirit to Terraform and CloudFormation but with a custom implementation emphasizing security (no direct credential exposure via public key encryption) and flexibility (any AWS region or environment).

## Key Topics

- **Primitives-Based Architecture**: Fine-grained AWS operations as individual API endpoints (S3, EC2, Lambda, ASG, Target Groups)
- **Secure Credential Handling**: Public key encryption pattern where orchestrator encrypts credentials and only AWS service can decrypt
- **Build Orchestrator Integration**: Orchestrator acts as "brain" calling AWS service endpoints in sequence
- **Multi-Mode Deployment**: Support for serverless (Lambda) and serverful (EC2/ASG) deployment targets
- **OSBot-AWS Library**: Leverages OWASP Security Bot toolkit's high-level AWS wrappers

## API Primitives

**S3 Bucket Management:**
- `POST /aws/s3/bucket/create` – Create bucket with configuration
- `GET /aws/s3/bucket/check` – Verify bucket existence
- `DELETE /aws/s3/bucket/delete` – Empty and delete bucket

**EC2 and AMI Operations:**
- `POST /aws/ec2/ami/create` – Create AMI from instance
- `POST /aws/ec2/instance/launch` – Launch instance from AMI
- `POST /aws/ec2/instance/run-command` – Execute commands via SSM

**Load Balancer and Auto Scaling:**
- `POST /aws/alb/target-group/create` – Create ALB target group
- `POST /aws/autoscaling/group/create` – Create ASG with target group

**AWS Lambda:**
- `POST /aws/lambda/create` – Create/update Lambda with Function URL
- `GET /aws/lambda/check` – Verify function status

## Credential Handling Workflow

1. Orchestrator requests AWS service's public key (`GET /aws/public-key`)
2. Orchestrator encrypts AWS credentials using public key
3. API calls include encrypted credentials in payload
4. AWS service decrypts with private key, executes operation
5. Credentials purged from memory after use
