## Overview

A comprehensive technical briefing on the Man-in-the-Middle (MITM) Proxy platform designed to intercept and process web traffic in real-time. The system captures HTTP(S) requests and responses from client browsers, applies custom processing (caching, content transformation), and forwards responses transparently to end users.

The architecture follows a modular design with a robust intercepting proxy, a flexible API-driven processing layer, and a dedicated HTML Graph Service for caching and content management.

## Key Topics

- **Request/Response Interception**: Two-hook architecture with `process_request` and `process_response` endpoints for custom processing at each stage
- **HTML Graph Service**: Caching and storage subsystem for persisting web content and metadata with flow logging
- **Cache Hit/Miss Workflow**: Immediate response on cache hit, upstream forwarding on miss with automatic caching
- **Simulation & Testing Tools**: UI tools to emulate browser requests and upstream responses without actual browsers
- **Performance & Scalability**: Stateless proxy design enabling horizontal scaling with minimal latency overhead

## Architecture Components

- **Client Browser**: Configured to use MITM proxy with trusted certificate for HTTPS interception
- **MITM Proxy Server**: Battle-hardened intercepting proxy (Docker/EC2) handling request/response hooks
- **MITM Proxy API Service**: Python/FastAPI service with `process_request` and `process_response` endpoints
- **HTML Graph Service**: Caching layer with Save HTML, Load HTML, and flow logging capabilities
- **Upstream Web Server**: External target servers unaware of interception

## Request Flow

1. Browser sends request to MITM Proxy
2. Proxy intercepts and calls `process_request` API
3. API checks cache (hit returns content, miss instructs proceed)
4. On cache miss, proxy forwards to upstream server
5. Upstream response intercepted, `process_response` called
6. Content cached in HTML Graph Service
7. Response forwarded to browser
