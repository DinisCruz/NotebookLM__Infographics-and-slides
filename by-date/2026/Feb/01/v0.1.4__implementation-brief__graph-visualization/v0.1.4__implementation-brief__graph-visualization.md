### Bug-5: Create Button Disappears After First Issue

#### Current Understanding

After creating one issue via the Kanban board "+" button or the "Create Issue" modal, the "Create bug/task/feature" buttons become unavailable. The user sees only "Creating..." in a disabled state.

**Root Cause Hypothesis:** The create modal or Kanban component enters a "creating" state when the create action is triggered, but the state is not properly reset after completion (success or failure).

#### Technical Analysis

```
┌─────────────────────────────────────────────────────────────────┐
│  Current Flow (Buggy)                                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  User clicks "+"  →  Modal opens  →  Submit  →  API call        │
│                           │                         │           │
│                           ▼                         ▼           │
│                    isCreating = true         (success/error)    │
│                           │                         │           │
│                           ▼                         X           │
│                    Button disabled          isCreating NOT reset│
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### Implementation Plan

1. **Locate the state management** in `create-node-modal.js`
2. **Ensure state reset** in both success and error paths:
   ```javascript
   async handleSubmit(e) {
       e.preventDefault();
       this.isCreating = true;
       this.render();

       try {
           const response = await window.issuesApp.graph.createNode(data);
           if (response.success) {
               this.closeModal();
               // Reset state
               this.isCreating = false;
           } else {
               // Handle error AND reset state
               this.isCreating = false;
               this.showError(response.message);
           }
       } catch (error) {
           // Reset state on exception
           this.isCreating = false;
           this.showError(error.message);
       }
   }
   ```

3. **Also check Kanban "+" buttons** - ensure they re-enable after modal closes

#### Files to Modify/Create

- `v0.1.4/components/create-node-modal/create-node-modal.js` (override)
- Potentially `v0.1.4/components/kanban-board/kanban-board.js` (if button state is local)

### Task-14: Integrate graph-service with Graph Traversal API

#### Current Understanding

Backend v0.2.20 added a new endpoint:
```
GET /nodes/api/nodes/{node_type}/{label}/graph?depth=N
```

This returns:
```json
{
  "success": true,
  "root": "Feature-11",
  "depth": 2,
  "nodes": [{ "label", "title", "node_type", "status" }],
  "links": [{ "source", "target", "link_type" }]
}
```

The UI needs a `getNodeGraph()` method in the graph service to call this endpoint.

#### Implementation Plan

Add to `graph-service-override.js`:

```javascript
/**
 * Get node with connected nodes for graph visualization
 * @param {string} nodeType - Type of root node (bug, task, feature, etc.)
 * @param {string} label - Label of root node (Bug-1, Feature-11, etc.)
 * @param {number} depth - Link hops to traverse (default: 1, max: 3)
 * @returns {Promise<{success, root, nodes, links, depth}>}
 */
graphService.getNodeGraph = async function(nodeType, label, depth = 1) {
    try {
        const response = await fetch(
            `/nodes/api/nodes/${nodeType}/${label}/graph?depth=${depth}`
        );
        const data = await response.json();

        if (data.success) {
            this._emit('graph-loaded', {
                root: data.root,
                nodeCount: data.nodes.length,
                linkCount: data.links.length
            });
        }

        return data;
    } catch (error) {
        this._emit('api-error', { operation: 'getNodeGraph', error: error.message });
        return { success: false, nodes: [], links: [], message: error.message };
    }
};
```

#### Caching Strategy

```
┌─────────────────────────────────────────────────────────────────┐
│  Graph Cache Structure                                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  _graphCache = Map {                                            │
│    "feature:Feature-11:2" → { nodes, links, timestamp }         │
│    "bug:Bug-5:1"          → { nodes, links, timestamp }         │
│  }                                                              │
│                                                                 │
│  Cache key format: "{nodeType}:{label}:{depth}"                 │
│  Cache TTL: 30 seconds (graphs change frequently)               │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```
