# v0.1.3 Brief: Issue Editor & Graph Visualization

## Why This Exists

**The Problem:** Traditional issue trackers (Jira, GitHub Issues, Linear) share a fundamental limitation: they live outside your codebase. Issues are stored in a separate database, accessed through a separate UI, and versioned separately from your code. This creates friction - and more importantly, it makes them invisible to AI coding assistants.

When you ask Claude Code to "fix the bugs in the backlog" or "implement the features planned for v2.0", it can't. It has no access to your issue tracker. You end up copy-pasting issue descriptions, manually briefing the AI, and losing the structure and relationships that make issue tracking valuable.

**The Insight:** What if issues were just files in your repo?

---

## What We Built

A **git-native, graph-based issue tracking system** where:

- **Issues are JSON files** in a `.issues/` folder, committed alongside your code
- **Relationships are first-class** - issues link to each other (blocks, depends-on, has-task) forming a graph
- **Node types are extensible** - bugs, tasks, features, versions, user stories, people
- **Status is just a field** - drag-drop in Kanban UI writes directly to the JSON file
- **Everything versions together** - branch your issues with your code, merge them together

```
your-repo/
├── src/
├── tests/
└── .issues/
    ├── config/
    │   ├── node-types.json      # Define: bug, task, feature, version...
    │   └── link-types.json      # Define: blocks, depends-on, has-task...
    └── data/
        ├── bug/
        │   └── Bug-1/node.json
        ├── feature/
        │   └── Feature-11/node.json
        └── version/
            └── Version-1/node.json   # Links to Feature-11, Feature-12...
```

---

## How It Changes Everything

Because issues are files that AI can read, a new workflow emerges:

| Traditional Workflow | Git-Native Workflow |
|---------------------|---------------------|
| Human writes issue in Jira | Human records voice memo |
| Human copy-pastes to AI | Claude Chat converts to structured JSON |
| AI has no context | Human refines in visual Kanban UI |
| Manual back-and-forth | Commits to Git |
| Human updates Jira manually | Claude Code checks out repo, reads `.issues/` |
| | Implements based on 'todo' column |
| | Human drags to 'done', repeat |

**The key unlock:** Claude Code can now understand your entire project plan - not just the code, but the *intent* behind it. It sees which features are planned, which tasks are blocked, who's assigned to what, and what version everything targets.

## The Workflow in Action

This brief demonstrates something powerful: **we are using the issue tracking system to plan and communicate its own development**.

### How It Works

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        THE DEVELOPMENT LOOP                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│   1. HUMAN records voice memo with ideas, features, tasks                   │
│            ↓                                                                 │
│   2. CLAUDE (chat) transcribes and converts to structured issues            │
│      - Creates Version, Feature, Task nodes as JSON                         │
│      - Establishes graph links (has-feature, has-task, depends-on)          │
│            ↓                                                                 │
│   3. HUMAN reviews in UI, refines:                                          │
│      - Drags issues to correct Kanban column (todo, in-progress, etc)       │
│      - Edits titles, descriptions, adds details                             │
│      - Adjusts relationships                                                 │
│            ↓                                                                 │
│   4. Issues committed to Git (.issues/ folder)                              │
│            ↓                                                                 │
│   5. CLAUDE CODE checks out repo, reads issues from 'todo' column           │
│            ↓                                                                 │
│   6. Claude Code implements changes based on issue specs                    │
│            ↓                                                                 │
│   7. Code committed back to repo                                            │
│            ↓                                                                 │
│   8. HUMAN reviews in UI, drags completed issues to 'done'                  │
│            ↓                                                                 │
│   (repeat from step 1 or 3)                                                 │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### What Makes This Powerful

1. **Voice-to-Issues** - Brain dump via voice memo → structured graph of issues
2. **Git-Native** - Issues are JSON files in the repo, versioned alongside code
3. **Graph Structure** - Version → Features → Tasks hierarchy with typed links
4. **Visual Kanban** - Drag-drop status changes that persist to disk
5. **LLM-Readable** - Claude Code can parse the `.issues/` folder directly
6. **Bidirectional** - Both human and AI can create/update issues
7. **Multi-Claude** - Claude Chat creates issues, Claude Code implements them

```json
{
  "type_id": "a1b2c3d4",
  "name": "version",
  "display_name": "Version", 
  "description": "Release milestone grouping features and tasks",
  "color": "#f59e0b",
  "statuses": ["planned", "in-progress", "released", "deprecated"],
  "default_status": "planned"
},
{
  "type_id": "e5f6a7b8",
  "name": "user-story",
  "display_name": "User Story",
  "description": "User need or scenario driving a feature",
  "color": "#06b6d4", 
  "statuses": ["draft", "ready", "in-progress", "implemented", "validated"],
  "default_status": "draft"
}
```

### New Link Types (link-types.json)

```json
{
  "link_type_id": "7a8b9c0d",
  "verb": "has-feature",
  "inverse_verb": "feature-of",
  "description": "Version contains feature",
  "source_types": ["version"],
  "target_types": ["feature"]
},
{
  "link_type_id": "5c6d7e8f", 
  "verb": "has-story",
  "inverse_verb": "story-of",
  "description": "Feature driven by user story",
  "source_types": ["feature"],
  "target_types": ["user-story"]
}
```
