### Bug-7: Modal Data Lost on Outside Click

#### Current Problem

When creating a new issue, if the user accidentally clicks outside the modal overlay, the modal closes and all entered data (title, description, tags) is lost without warning.

#### User Flow (Current - Buggy)

```
┌─────────────────────────────────────────────────────────────────┐
│  User Flow: Creating an Issue (Current Bug)                     │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. User clicks "+ New"                                         │
│     ┌──────────────────────────────────────────────────┐        │
│     │  Create New Task                            [X]  │        │
│     │  ─────────────────────────────────────────────── │        │
│     │  Title: "Add user authentication"                │        │
│     │  Description: "We need OAuth2 support for..."    │        │
│     │  Tags: "security, auth, priority"                │        │
│     │                                                  │        │
│     │  [Cancel]                     [Create Task]      │        │
│     └──────────────────────────────────────────────────┘        │
│                              │                                  │
│                              │ User accidentally clicks         │
│                              │ outside modal (dark overlay)     │
│                              ▼                                  │
│  2. Modal closes immediately - ALL DATA LOST!                   │
│     User frustrated, has to re-enter everything                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### Proposed Solution

Two options:

**Option A: Disable click-outside-to-close (Recommended)**
- Only allow closing via Cancel button or X button
- Most straightforward, prevents accidental data loss

**Option B: Confirm before closing if form has data**
```javascript
handleOverlayClick(e) {
    if (e.target.id === 'cnm-overlay') {
        if (this.hasUnsavedData()) {
            if (confirm('Discard unsaved changes?')) {
                this.close();
            }
        } else {
            this.close();
        }
    }
}
```

#### Implementation Plan

1. Modify `create-node-modal.js` overlay click handler
2. Check if form has data before closing
3. Either disable overlay click or show confirmation

#### Files to Modify

- `v0.1.5/components/create-node-modal/create-node-modal.js`

### Task-19: Add Mermaid.js Graph Visualization

#### Why Mermaid.js?

- **Declarative syntax** - text-based graph definition
- **Documentation-friendly** - widely used in GitHub/GitLab markdown
- **Auto-layout** - no manual positioning required
- **Easy export** - users can copy graph definition for docs

#### Implementation Plan

1. Add Mermaid.js CDN to `index.html`
2. Create `graph-viewer-mermaid.js` component
3. Convert API response to Mermaid syntax
4. Add visualization mode toggle in graph-viewer toolbar
5. Support export of Mermaid code

#### Data Transformation

```javascript
// Convert API response to Mermaid syntax
function toMermaidSyntax(graphData) {
    const lines = ['graph TD'];

    // Add nodes with styling
    graphData.nodes.forEach(node => {
        const shape = getNodeShape(node.node_type);  // feature=hexagon, task=rect, bug=diamond
        lines.push(`    ${node.label}${shape}`);
    });

    // Add edges
    graphData.links.forEach(link => {
        if (link.link_type) {
            lines.push(`    ${link.source} -->|${link.link_type}| ${link.target}`);
        } else {
            lines.push(`    ${link.source} --> ${link.target}`);
        }
    });

    return lines.join('\n');
}

// Example output:
// graph TD
//     Feature-12{{Feature-12}}
//     Task-14[Task-14]
//     Feature-12 -->|has-task| Task-14
```

### Task-20: Add Vis.js Graph Visualization

#### Why Vis.js?

- **Performance** - excellent with large graphs
- **Rich interactions** - clustering, physics, hierarchical layouts
- **Touch support** - good mobile experience
- **Built-in clustering** - automatically group dense regions

#### Implementation Plan

1. Add Vis.js Network CDN to `index.html`
2. Create `graph-viewer-visjs.js` component
3. Map API response to Vis.js DataSet format
4. Add layout options: hierarchical, physics-based, circular
5. Support node clustering for large graphs

#### Data Transformation

```javascript
// Convert API response to Vis.js format
function toVisJsFormat(graphData) {
    const nodes = new vis.DataSet(
        graphData.nodes.map(node => ({
            id: node.label,
            label: node.label,
            color: getNodeColor(node.node_type),
            shape: getNodeShape(node.node_type),
            title: node.title || node.label  // Tooltip
        }))
    );

    const edges = new vis.DataSet(
        graphData.links.map((link, i) => ({
            id: i,
            from: link.source,
            to: link.target,
            label: link.link_type || '',
            arrows: 'to'
        }))
    );

    return { nodes, edges };
}
```

// Convert API response to Cytoscape format
function toCytoscapeFormat(graphData) {
    const elements = [];

    // Add nodes
    graphData.nodes.forEach(node => {
        elements.push({
            data: {
                id: node.label,
                label: node.label,
                type: node.node_type,
                title: node.title
            },
            classes: node.node_type  // For styling
        });
    });

    // Add edges
    graphData.links.forEach((link, i) => {
        elements.push({
            data: {
                id: `edge-${i}`,
                source: link.source,
                target: link.target,
                label: link.link_type || ''
            }
        });
    });

    return elements;
}

// messages-service.js - Add confirm method
messages.confirm(text, options) {
    // Returns a Promise that resolves to true/false
    return new Promise((resolve) => {
        const id = this.add('confirm', text, {
            confirmLabel: options.confirmLabel || 'Confirm',
            cancelLabel: options.cancelLabel || 'Cancel',
            confirmStyle: options.confirmStyle || 'primary',  // 'primary', 'danger'
            onConfirm: () => { this.dismiss(id); resolve(true); },
            onCancel: () => { this.dismiss(id); resolve(false); }
        });
    });
}

// Usage in node-detail.js
async handleDelete() {
    const confirmed = await window.issuesApp.messages.confirm(
        `Delete ${this.state.node.label}? This cannot be undone.`,
        { confirmLabel: 'Delete', confirmStyle: 'danger' }
    );
    if (confirmed) {
        await this.deleteNode();
    }
}
```

### Task-25: Open Issue in New Tab from Kanban

#### Current Problem

Users cannot open an issue in a new browser tab from the Kanban board. They have to:
1. Click to navigate
2. Copy URL
3. Open new tab
4. Paste URL

#### Proposed Solution

1. Make cards work with browser's native "Open in New Tab" (Cmd/Ctrl+Click, right-click)
2. Use proper anchor links with hash URLs

#### Technical Approach

```
┌─────────────────────────────────────────────────────────────────┐
│  Implementation Options                                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │

│  card.addEventListener('click', (e) => {                        │
│    if (e.metaKey || e.ctrlKey) {                                │
│      window.open(`#/issue/${label}`, '_blank');                 │

#### Implementation Plan

1. Wrap kanban cards in `<a>` tags with proper `href="#/issue/{label}"`
2. Handle regular click to prevent default and use SPA navigation
3. Let Cmd/Ctrl+Click and right-click use native browser behavior
4. Ensure drag-and-drop still works (start drag on mousedown, not click)
